# ADR 0032: Frozen prepared export and v9 migration

Status: accepted for PR 7.

All UI export actions now evaluate one canonical prepared snapshot. The shared provider passes that exact frozen readiness object to sheet preview and output controls. Runtime template drafts receive their own inspection snapshot; they cannot enter Manufacture. Canonical preparation removes explicit closing repeats and redundant collinear boundary vertices, classifies winding/nesting, checks simple contours, and detects partial collinear duplicate cuts. Kerf/perforation preparation remains non-destructive. The final prepared geometry is validated again after compensation.

Placement certification uses triangulation and polygon clipping of rotated/transformed outer contours minus holes. Bounding rectangles only prune checks. Parts may nest inside genuine holes or concave empty regions. Positive-area material intersections above 1e-8 square mm block production, as do duplicated cut segments, invalid sheet dimensions/margins, off-sheet geometry, missing or duplicate placements, open/unverified perimeters, missing source references and lost output operations.

Readiness distinguishes blocked serialization, inspection draft and production. Production requires current validated generation and acknowledgement of fabrication warnings. Last valid finite geometry and historical open paths remain available through explicitly named draft SVG/PDF actions. A draft filename and provenance mark its status; it is never presented as cutting-ready. Nominal geometry and digital assembly do not establish physical fit. Warning acknowledgements do not alter the generation signature.

Profiles are Laser SVG, Print assembly PDF and Inspection SVG. Laser output excludes guide paths and printable labels; assembly/inspection keep them. SVG retains one-to-one mm and operation layers. All occupied sheets download sequentially as separate, padded sheet-number files with a visible browser notice; no zip dependency is added. PDF uses every occupied sheet. Writers receive the frozen prepared parts and layouts directly, avoiding a second kerf computation. Metadata includes schema, algorithm, input hash, snapshot hash, profile and draft status.

All project JSON and new IndexedDB records now use v9. Older named records and the autosave pointer migrate through the existing database/key schema without recomputing or deleting user geometry. New generation records use signature v3 while v2 records remain readable; legacy v2 geometry stays inspectable and requires regeneration for cutting readiness. Strict import limits apply to file and storage entry points: 20 MiB file, 100,000 indexed triangles, 10,000 fabrication paths and bounded nesting; native caches also have 200-face bounds, source half-edge/pose correspondence, graph compilation, exact perimeter and crease checks. Stale intent remains saveable.

Historical low-level `createSvgDocument`, `createSheetSvgDocument` and `createAssemblyPdf` inspection serializers retain literal v8 vector metadata when called without a prepared snapshot. This keeps all PR 0 byte baselines intact, including the documented invalid frustum oracle. UI production and draft downloads go through `writePreparedOutput` and carry v9 provenance. No legacy golden is replaced to conceal invalid geometry.
